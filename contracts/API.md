# Shared core API (initial implementation)

`@veguide/core` exports from `packages/core/src/index.ts`. All exact TypeScript contracts are in `src/types.ts`.

```ts
analyzeText(input: CheckInput | string, now?: () => Date): CheckResult
checkProduct(input: CheckInput, options: CheckOptions): Promise<CheckResult>
lookupProduct(barcode: string, options?: { fetch?: typeof fetch; signal?: AbortSignal; now?: () => Date; category?: Category; market?: string; locale?: 'de'|'en' }): Promise<DatabaseProduct | null>
createOpenAIProvider(config: ProviderConfig, fetch?: typeof fetch): ProviderAdapter
parseAIExtraction(json: string): AIExtraction
```

`CheckInput`: optional `text`, `barcode`, `name`, `brand`, `category`, `complete`, `market`, `locale`, `sourceUrl`, `images` (locally sanitized JPEG/PNG/WebP data URLs). Categories: food, drink, cosmetics, household, clothing, shoes, other. `complete: false` overrides an ingredient-list heading. A heading infers a complete list for local text; without a heading the user must explicitly confirm completeness.

`CheckOptions`: required `mode: 'explicit' | 'background'`; optional `provider`, `fetch`, `signal`, `offline`, `now`. Offline disables all network requests, including a configured local provider. Background never invokes the provider. At most one initial AI analysis and one bounded identity-only research follow-up occur per check. Database requests use exact checksum-valid GTIN; names alone are never considered exact matches.

`ProviderAdapter.extract(input, signal?)` returns required `text`, `complete`, and `category`, with optional product identifiers and these bounded evidence fields:

- `ingredientAssessments`: at most 100 `{term, status, explanation}` entries. Only assessments matching an actual composition term can replace an unknown local finding. Known local animal/ambiguous findings remain authoritative. AI assessments are attributed separately from transcription.
- `labelObservations`: at most five `{kind, name, text}` entries. Explicit vegan labels/claims observed in supplied images can support a `packaging` result. Vegetarian, negated-vegan, and unsupported certification names do not establish a vegan label. Observations remain unverified.
- `webCompositions`: at most three `{url, text, complete, sourceType, productName, brand}` entries. `sourceType` is `manufacturer` or `retailer`; each list is limited to 20,000 characters. A completed provider search must contain the exact source URL, and product name/brand must match the identified variant. Retrieved composition stays separate from photo transcription and is evaluated with the same local/AI ingredient rules. It establishes composition evidence, never an explicit manufacturer vegan claim or certification. Conflicting accepted lists are retained.
- `webClaims`: at most five `{url, quote, claim, sourceType, productName, brand}` entries. Claims are ignored unless a supported adapter reports an actual completed web search, the exact URL is in its consulted sources, and the product name/brand match.
- `research`: adapter-only `{searched, sources: [{url, title}]}` provenance, bounded to 50 sources. It comes from provider tool output and citation annotations, including completed opened-page URLs. Model-authored JSON cannot set this field.

Use `parseAIExtraction` on raw model text; it rejects model-supplied research metadata. A trusted provider/native adapter may attach validated transport metadata before returning its result. The canonical prompt is `contracts/ai-extraction-prompt.json`, exported as `EXTRACTION_PROMPT`; model-output bounds are in `ai-extraction.schema.json`. The pipeline revalidates adapter output. AI cannot set result status or invent company concerns. Text-only extraction must preserve the entire original text or the entire composition following its heading. A user-confirmed complete text list remains authoritative when photos are also supplied, so image transcription cannot silently replace it with a shorter list. Text completeness is never promoted by AI alone.

`ProviderConfig`: `baseUrl`, `model`, optional `token`, `supportsVision`. The provider requires HTTPS except loopback HTTP; disables redirects/cookies; caps requests, input, images and timeout; rejects unfinished completions. The official `https://api.openai.com/v1` endpoint uses `/responses` with `web_search`, `store:false`, consulted-source metadata, and at most three tool calls. Other compatible endpoints use `/chat/completions` without search. `ProviderAdapter.supportsWebSearch` advertises this distinction. The companion's ChatGPT Responses implementation remains separate; its endpoint accepts the web-search tool but not the API-only `max_tool_calls` parameter, so its search limit is expressed in the prompt.

`CheckResult` contains `schemaVersion:1`, `id`, `outcome` (vegan/not_vegan/uncertain/conflicting), `basis` (certified/manufacturer/composition/packaging/insufficient), `title`, `summary`, `category`, `identity`, `findings`, `evidence`, `questions`, `warnings`, `crossContact`, `companyConcerns`, `checkedAt`, `usedAI`. Optional `aiStatus` is `not_needed`, `disabled`, `offline`, `unconfigured`, `vision_disabled`, `failed`, `text`, or `images`; optional `webSearchStatus` is `searched`, `not_used`, or `unsupported`. These describe execution, independently of the vegan outcome. Optional `aiError: {code, message}` retains a fixed localized failure explanation: codes are `authentication`, `access_denied`, `quota`, `rate_limit`, `timeout`, `network`, `unsupported_model`, `invalid_response`, `incomplete_response`, `request_rejected`, `service`, or `unknown`. It does not contain raw provider errors. Android history import/export regenerates messages from recognized codes and drops unrecognized errors. Evidence kinds include `ocr` for on-device photo text, distinct from supplied user composition.

Source rules: `data/rules.json` with exact phrase aliases and localized explanations. `plant` denotes absence of an identified animal source and includes mineral/synthetic terms. Unknown terms block positive composition verdicts unless an attributed AI assessment resolves them. Additive-role prefixes, decimal percentages, and recognized processing modifiers are normalized; arbitrary parenthesized subingredients are preserved. Equivalent findings from supplied text and AI transcription are deduplicated. Drink processing aids and hidden clothing/shoe components require more evidence even with recognized materials. Fixtures: `fixtures/composition.json` shared with Kotlin.

`applyVerifiedEvidence` is for callers that have independently verified exact product/variant scope. It is not called with raw AI claims or database label tags. `verification: source` for manufacturer evidence means the caller verified the linked original source. AI-read web claims follow a separate path: consulted URL and product identity are checked, but source interpretation is explicitly unverified. Manufacturer claims use basis `manufacturer`; AI-read certification sources and visible vegan labels use `packaging`, never independently verified `certified`. Contradictory animal/vegan evidence stays conflicting. There is no independent automated registry or manufacturer-source verifier yet.

Database cache is memory-only (100 records, 24h positive/5m negative) with 15 requests/minute/database. This bounds a live background worker; persistent cache and shared rate limiting across worker restarts belong to the extension. Germany matching rejects known non-German records. Other market matching is not implemented yet; choose DE for the initial client UI.

Community database composition fields are not assumed complete. They can establish a named animal ingredient; a positive full-list result requires an independently complete list. Database vegan label tags are displayed as unverified metadata and never promoted to certification. This intentionally favors uncertain results over falsely reassuring database badges.

Sources checked 2026-10-05: [Open Facts API](https://openfoodfacts.github.io/openfoodfacts-server/api/), [OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat), [OpenAI web-search tools](https://developers.openai.com/api/docs/guides/tools-web-search), and [ChatGPT open-source integration limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). No product records or images are bundled. Open Facts attribution and ODbL/DBCL licenses stay on individual evidence items. Rules are original short classifications, not copied taxonomy data.

An incomplete recognized product can trigger one additional research request when a search-capable provider skipped search. The request contains only product identity, category and locale/market, uses required web-search tool selection, and cannot overwrite the original visible composition, identity or photo labels. The overall request budget is 130 seconds. Failed or invalid follow-up responses preserve the completed first extraction. The shared `researchPrompt` supplements the full extraction prompt; it is not a separate schema.

Finding `term` remains the original source identity. Optional paired `displayTerm` (1–300 characters) and `displayLocale` (`en`/`de`) are display-only translations and must never affect classification or overwrite evidence text. History transfer preserves these fields. Result and history contracts remain version 1 while unreleased.
